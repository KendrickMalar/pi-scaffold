# TBD（段階1: deterministic-scaffold 0.13.0）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 対象リポジトリに TBD（`Scope: TBD` の Issue）を作る道具と、TBD から Epic を作って TBD を閉じる道を足す。

**Architecture:** 管理ブロックの新しい kind `tbd` を contracts・render・codec に足す。`scaffold_tbd_create` は `scaffold_epic_draft_create` と同じ発行経路（template snapshot → validate → submit → 読み戻し、operationId で冪等）。`scaffold_epic_draft_create` に任意の `tbdIssue` を足し、TBD を生で読み（管理ブロックの有無どちらも）、Epic 作成の後に `gh_issue_close_if_current` で TBD を閉じる。

**Tech Stack:** TypeScript、node:test（`npm test` = build + `node --test dist/test/*.test.js`）、TypeBox、FakeDeterministicGh

**Spec:** `docs/superpowers/specs/2026-11-17-tbd-design.md`（末尾の「段階1での改訂」が優先）

## Global Constraints
- TBD のラベルは `Type: Scaffold`＋`Scope: TBD`。色 `d4c5f9`、説明「Epic になる前の要望（TBD）」
- 版は 0.13.0。GitHub への書き込みは deterministic-gh の道具だけ
- 既存の Epic（`sourceTbd` 無し）の本文・digest は変えない
- コード中のコメント・識別子は英語、利用者向け文言は日本語（既存に合わせる）

## Review Focus
- 管理ブロックの無い TBD（Moja・人が作ったもの）→ 題＋本文が originalRequest になり、Epic ができ、TBD が閉じる
- 既に閉じた TBD、`Scope: TBD` の無い Issue、別リポジトリ・PR → Epic を作らず blocked
- 同じ operationId での再実行（Epic 作成後・TBD を閉じる前に落ちた）→ Epic を二重に作らず、TBD を閉じて終わる
- TBD の本文が読み始めから変わった → close は precondition で拒まれ、Epic は残る（partial/blocked で報告）
- `tbdIssue` 無しの従来の呼び出し → 今と同じ結果（既存試験がそのまま通る）
